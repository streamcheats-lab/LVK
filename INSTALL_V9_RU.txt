LVK v9 — исправление выделения чатов и фоновых Web Push

1) Сделай резервную копию текущего сайта.
2) Распакуй архив. Скопируй содержимое LVK-main в корень репозитория LVK (с заменой файлов).
3) ВАЖНО: перед публикацией открой lvk-push-config.js. В нём должен быть ТВОЙ ДЕЙСТВУЮЩИЙ publicKey, совпадающий с LVK_VAPID_PUBLIC_KEY в Supabase. Если после настройки VAPID ты менял ключ на GitHub, скопируй свой актуальный ключ в этот файл; архив мог содержать более старое значение.
4) GitHub Desktop: Commit to main -> Push origin. Дождись успешной публикации GitHub Pages.
5) Supabase -> Edge Functions -> lvk-push -> Code: при необходимости обнови серверную функцию содержимым файла supabase/functions/lvk-push/index.ts, затем Deploy. Этот шаг необходим для исправления Push ответов поддержки; для личных сообщений/групп нужно также проверить действующие вебхуки и секреты.
   Важно: файл Edge Function НЕ выполняется в SQL Editor.
6) На КАЖДОМ устройстве: войди в аккаунт LVK -> Профиль -> Включить уведомления -> Разрешить. Проверь, что браузер показал "Подписка сохранена в Supabase".
7) Supabase -> SQL Editor, выполни:
   SELECT user_id, count(*) AS devices FROM public.lvk_push_subscriptions GROUP BY user_id;
   Если 0, Push в фоне работать не сможет.
8) Для теста: два разных аккаунта, отправь личное сообщение со второго на первый, когда LVK на первом устройстве закрыт (но браузер/ОС допускает фоновые уведомления). Проверь Edge Function Logs и HTTP ответы webhook. Android: отключи ограничения фоновой работы для браузера/PWA, проверь разрешение уведомлений. iPhone: Web Push доступен для установленного на домашний экран PWA, с разрешением пользователя, начиная с iOS 16.4.

Примечание: отправка в фоне зависит от корректной доставки database webhook -> lvk-push -> push service и разрешений ОС. Этот архив не может изменить серверные секреты/вебхуки в твоём аккаунте автоматически. Не публикуй PRIVATE KEY.
